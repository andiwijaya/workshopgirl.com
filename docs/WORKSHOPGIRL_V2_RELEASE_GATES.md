**Cache attack path:** an application would need to use the package in a shared HTTP response cache with authenticated/user-specific responses and affected stale-response reuse. This repository deploys `dist` as static HTML/assets (`output: 'static'`), has no server adapter, authenticated backend or shared user-response cache, and uses local native image assets. The installed Astro import is `dist/assets/build/remote.js`: remote-image loading/revalidation constructs a `CachePolicy` and computes TTL; no private record or browser upload enters it. Source inspection found no `astro:assets` remote image input, remote-image allowlist or dynamic server route. Instrumented production build calls zero `CachePolicy` constructors. The package is declared under production dependencies in npm, but is **not browser/deployed runtime code** in this release. Therefore the advisory's cross-user disclosure path is absent, not accepted as a reachable high confidentiality risk.

**Brace attack path:** a hostile deeply nested brace pattern must reach the recursive parser/compiler/expander to terminate the Node process. The installed Astro parser imports fast-glob in its old TypeScript-project-list resolver, where inputs are `parserOptions.project` and project-folder ignore config. Repository lint uses the checked-in `./tsconfig.json` and fixed ignore paths; customer/job fields, image/audio names/contents, URL fragments and browser form input never reach lint or glob patterns. Instrumented full lint and build call zero brace entrypoints. Untrusted repository/config changes are outside this input boundary and must be reviewed before CI execution. There is no network pattern endpoint or browser bundle containing this dependency chain.

`scripts/audit-dependency-exposure.ts` wraps the installed CommonJS exports without changing their behavior and writes call evidence at process exit. The successful final lint/build traces contain zero vulnerable API calls; a separate harmless sanity run observes exactly one `CachePolicy` construction and `{a,b}` brace parse, proving the probes are active. This is observed reachability plus source/architecture review, not a blanket immunity proof or a formal penetration test.

## Local job-context transport

Generated links now use `/tools/workshop/<module>/#job=<encoded-local-id>`. The browser stores the fragment in its tab/history and carries it when opening the same-origin link in a new tab; HTTP request targets and Referer headers exclude it. There is no global last-job session/localStorage fallback: an unqualified route is deliberately neutral, and opening a link in a different browser/profile cannot resolve a record it does not possess. Job/customer records and the existing v1 storage key/v2 schema are unchanged.

One helper, `localJobHref`, constructs generated links; `workshopJobParams` reads fragment context and retains legacy query precedence. Shared tabs/progress, job pickers, Intake/Inspection/Work/QC continuations, dashboard resume, queue actions, Parts Work Order links, Procurement job links, History completed-job links and both Engine attachment links use this transport. Billing, Parts and History consume the same exact local selection. Only a single exact ID present in the validated local store selects a job; missing, malformed, repeated, deleted and foreign-profile IDs become neutral without changing records. Selecting a job or clearing a native picker updates the current history entry using `replaceState`; cross-page links and same-page job-picker links create normal navigation entries.

On Workshop pages a native fragment/history change reloads the static module, reinitializing forms as well as navigation so a new context cannot retain the previous job's closures. Restored bfcache pages reload to validate local records. `replaceState` does not emit a hashchange or cause a reload when saving/selecting within a form. In-page accessibility anchors focus/scroll their target without replacing the job fragment. Explicit Start new / All jobs / Clear context links remain unqualified. Storage events and tab-link pointer/keyboard actions revalidate deleted selections before propagating them.

`LocalJobContext.astro` runs inline in the head of operations, discovery and analyzer/tool pages before explicit resource elements. It moves **all** legacy `job` query values to the fragment and removes the query field with `replaceState`, preserving unrelated public query fields and repeated-ID invalidity. A head `no-referrer` policy additionally protects resource requests and outgoing navigation. After module initialization the URL retains only a validated local job fragment. A request for an incoming `?job=` URL has already reached the host before any page JavaScript runs: **that initial document request cannot be unsent**. Sanitization prevents further propagation, not retroactive erasure from host/CDN logs or previously copied links.

Canonical/OG URLs and generic native share/clipboard/social links remain static public URLs without query, fragment, job IDs or record contents. Tool clipboard fallback also strips query/fragment if canonical metadata is missing. Operations and analyzers have no analytics integration/events; existing optional Home GA configuration strips location/referrer query/hash and is tested with private synthetic values. Fragments are local navigation state, not secrets or access controls: manually copying the address bar/history can include the opaque ID. Generic Share tool deliberately excludes it; private record print/export remains an intentional local user operation. Browser print invocation and subsequent requests are checked, not a physical printer or OS PDF dialog.
